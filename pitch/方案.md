### 作品简介（一句话）

戴上耳机走在街上，手机实时听出周围的节奏和音高，让你正在听的歌跟上脚步、车轮、街头艺人的拍子，并移到环境的调上：世界成了你这首歌的伴奏。跑步时它是会"带"你提速的步频电台；想安静时，它把此刻的时间、天气和街声生成一段只属于此刻的声景。

### 创作思路

耳机现在有两种模式：降噪把世界关在外面，通透把世界放进来。但不管哪种，你的歌和你身边的世界都是两条互不相干的声轨。走路时脚步和鼓点总是错开；地铁进站的轰鸣、街头艺人的吉他，在耳机里都只是"噪音"。

我们想做第三种模式：**共鸣**。让世界成为你这首歌的一部分。

- **对拍**：听出环境里的节奏（你的脚步、转向灯、车轮、街头艺人的鼓），歌曲的速度平滑地滑过去，每一拍都落在世界的拍点上。
- **定调**：听出环境里持续的音高（发动机的嗡鸣、风铃、街头艺人弹的调），歌曲移调，让嗡鸣成为新调的主音或属音。
- **入景**：拍一下眼前，AI 根据画面调混响、明暗、编配和大小调。

同一个"听世界"的引擎还支持另外两个场景：

- **跑步**：数出你的步频，自动挑最合拍的歌，锁到你的脚步上。设了目标步频时，音乐先快一点点（最多 3%），把你"带"上去，到了目标再锁回脚步。
- **声景**：不放歌。时间、天气、你的步子、身边的嗡鸣，实时生成一段永不重复的声景，用于专注、放松、散步和入睡。

一个地方"听起来"的拍子和调，由在场的人贡献成"共鸣指纹"，慢慢拼出一张城市的节拍地图。"共鸣片段"可以一键保存分享，记录的是"这条街和我的歌合奏了"。

## 二、问题洞察

1. **音乐和环境互相打架。** 通勤、散步、跑步是听歌最多的场景，但耳机里的拍子和脚下的步子、身边的声音从来不同步。降噪只能把世界关掉，通透只能把世界原样放进来。
2. **"环境"在音乐产品里一直是缺席的。** 推荐系统会看你是谁、几点、心情如何，却从不"听"你周围在发生什么。
3. **街头的音乐性被浪费了。** 转向灯的嗒嗒声、列车的节奏、街头艺人的调，本来都可以是音乐的一部分。

## 三、解决方案

| 能力 | 怎么做 | 实测（Demo 中） |
| --- | --- | --- |
| **对拍** | 麦克风接 AudioWorklet，每 10.7 ms 算一次低频 / 全频能量的起音强度。对最近 6 秒做自相关，估计速度，用"梳子"滑动估计相位；手机端再用加速度计识别脚步。歌曲每拍把速度向目标滑动 35%，相位每拍最多修正 6%，所以听起来是被世界"带着走"，而不是跳拍。环境里的重音还会对音乐做轻微的侧链压缩 | 模拟街头声（112 BPM 脚步）：约 5 秒锁定，相位差从 180 ms 收敛到 0–2 ms |
| **定调** | 16384 点 FFT，只取频谱的局部峰值，折叠成 12 个音级（chroma）。一个音级明显压过其他时判为嗡鸣；能量分散但和某个调高度相关时，用 Krumhansl–Schmuckler 调性轮廓识别 24 个调。嗡鸣作新调的主音或属音，取移动最少的那个；移调只在小节线生效 | 110 Hz 嗡鸣：约 1.5 秒识别为 A，《夜行》从 E 小调移到以 A 为属音的 D 小调 |
| **入景** | 拍一张照片，多模态模型（腾讯混元）给出能量、效价、情绪；画面明暗由浏览器本地计算，地点类型决定混响空间 | 映射到编配密度、低通明暗、大小调和混响（小房间 / 开阔户外 / 隧道 / 现场） |
| **原创生成曲** | 5 首按"级数"记谱、浏览器里实时合成的原创曲（鼓、贝斯、和弦铺底、琶音、旋律），速度和调都能无损连续变化 | 没有版权风险。正式曲目怎么支持，见第四节"可行性" |
| **共鸣片段** | 把环境声和音乐按"耳朵里听到的时刻"对齐（补偿输出和输入延迟），经限幅后录成 15 秒片段 | 对录下的片段做客观分析：锁定前，脚步和鼓点是两个分开的峰（错拍）；锁定后合并成一个峰 |
| **共鸣指纹** | 在现场贡献的拍子和调（**只存数字，不存声音**），按八度折叠后取中位数，调取多数票；下一个人可以"按它预调" | 地点页显示"这里的拍子：112 BPM · A 嗡鸣" |

**隐私**：环境声只在本机实时分析，不上传、不保存；只有用户主动录制的片段会留在自己手机上。

### 三种模式，一个引擎

| 模式 | 用户怎么用 | 关键做法 | 实测（Demo 中） |
| --- | --- | --- | --- |
| **街头** | 通勤、散步、遇到街头艺人 | 对拍 + 定调 + 入景（见上表） | 见上表 |
| **跑步** | 跑起来，或设一个目标步频 | 加速度计数步频 → 自动挑伸缩最少的曲子（一步一拍优先）→ 锁到脚步；设了目标时音乐最多领先 3%、不锁相位，到达后再锁回。实时统计时长、平均步频、**合拍率**（落脚点 ±60 ms 内踩在拍上的比例） | 合成 170 步/分：约 4 秒数准，自动选中 172 BPM 的《冲线》；跟随时相位差 0–5 ms，合拍率升到 80–97% |
| **声景** | 专注、放松、散步、入睡 | 不放歌，实时即兴：根音 + 五度的嗡鸣、在顺阶和弦间游走的铺底、五声音阶的钟琴、跟着步子的脉冲、雨声和风声层、放松 / 入睡时的呼吸起伏。输入是**时段**（决定调式和明暗）、**天气**（Open-Meteo）、**步子**、**环境里的嗡鸣**（决定根音）；环境安静时用这里的共鸣指纹定根音 | 小雨 17°C + 170 步/分 + A 音嗡鸣 → D 大调（A 作属音），有雨声层和风声层，脉冲跟着步子 |

**和已有产品的区别**

| | Spotify Running（已下线） | Endel | 共鸣 |
| --- | --- | --- | --- |
| 跟步频 | 按步频挑同速度的歌（少量原创曲可变速） | 运动状态影响声景 | 在一首歌**里面**逐拍对齐**相位**，并统计合拍率 |
| 主动引导 | 无 | 无 | 节拍引导：音乐先快一点，把你带到目标步频 |
| 听真实环境 | 无 | 据公开介绍，输入是时间、天气、心率、运动，不听环境声 | **听**：环境的节奏、嗡鸣和调直接决定音乐的拍子和根音 |
| 地点 | 无 | 只用到位置推算天气 | 共鸣指纹：每个地点"听起来"的拍子和调，众包积累 |
| 放的是什么 | 曲库里的歌 | 只有生成的声景 | 同一个引擎：街头 / 跑步对齐你的歌，声景生成音乐 |

### 为什么会有人主动用

- **每天都用得上**：通勤、散步、跑步，本来就是戴耳机听歌最多的场景，不需要改变习惯，只是多了一个开关。
- **结果当场就能感觉到**：脚步踩在鼓点上、地铁的轰鸣和歌在同一个调，这种"对上了"的感觉立刻就有。
- **跑步有量化反馈**：合拍率和节拍引导，让"跑得更有节奏"变成看得见的进步。
- **一天里都有用**：通勤用街头，运动用跑步，工作、午休、睡前用声景。
- **自带传播**：共鸣片段是独一无二的，每条街、每一刻录出来都不一样，天然适合分享。
- **越用越好**：共鸣指纹让后来的人一开始就在调上，地点越热门，体验越好。

## 四、对照评审标准

### 用户价值

- 把听歌和身边的世界连起来，改善的是每天通勤、散步、跑步的体验。
- 不需要学习，开关一开就能感受到。
- 共鸣片段和共鸣指纹让个人体验变成可以分享、可以留给后来者的东西。

### 可行性

- **全部跑在手机浏览器里**（Web Audio + AudioWorklet），不依赖服务器算力；Demo 可以直接部署上线。
- **可验证**：前端单元测试 34 项（多种速度、抖动与噪声下的节奏估计，相位，嗡鸣与调性识别，移调决策，按步频选歌，节拍引导，合拍率，天气解析与声景规划），服务端测试 98 项。端到端测试 23 步：用合成的街头声当假麦克风、合成的加速度当跑步、模拟的天气接口，在真实浏览器里断言 112 BPM 对拍、D 小调定调、170 步/分 的引导与锁定、声景的各项输入和片段下载。演示视频就是端到端测试录下来的。
- **正式曲目怎么支持（以及哪些不行）**：
  - 对整个曲库离线跑一次节拍跟踪和调性识别，播放时用相位声码器一类的算法实时变速、变调，不需要分轨。分轨（可以用 AI 分离）只用于"入景"的精细编配。
  - 节拍稳定的流行、电子、摇滚、说唱等大多数歌曲，可以实时对拍、定调。速度会变的歌，按节拍网格逐拍对齐。自由节奏的歌（古典的自由速度段落、氛围音乐、清唱）不对拍，但仍能定调和入景。
  - 音质限制调整幅度：速度在 ±10–15% 内、移调在 ±2–3 个半音内基本听不出来。差得更远时不硬改，而是**按速度和调选下一首歌**。这一步只用到离线算好的数据，对全曲库都适用。
  - 版权：播放时的实时变速变调，和播放器自带的倍速播放性质相近；但把改动后的版权歌曲录成片段分享，需要另行授权。正式版可以只分享"歌曲链接 + 共鸣参数"，由对方的 App 在本地重现。声景完全由生成产生，没有这个问题。
- **原生端**：可以用 react-native-audio-api 移植同一个引擎，也可以直接做进播放器。

### 创新性

1. **耳机的第三种模式**：降噪、通透之外的"共鸣"，从"隔绝 / 放行环境"变成"和环境合奏"。
2. **实时的环境 → 音乐控制**：以往的"跑步音乐"只看步频，而且只换歌；共鸣是在一首歌**里面**连续对齐拍子的相位，并且同时对齐调。跑步时它还会主动引导步频。
3. **会听的生成式声景**：已有的生成式声景只看天气、时间、心率；共鸣的声景还会听身边真实的声音，根音跟着街上的嗡鸣走。
4. **城市节拍地图**：每个地点"听起来"的拍子和调，由在场的人用数字贡献。这是一种以前没有的、可以众包的声音数据。

## 五、AI 在作品中的作用

| 环节 | AI / 算法 | 作用 |
| --- | --- | --- |
| 对拍 | 起音检测 + 自相关速度估计 + 梳状相位估计 + 平滑锁相 | 让歌落在世界的拍点上 |
| 定调 | 频谱峰值 → 音级 → 嗡鸣判定 / Krumhansl 调性识别 → 最小移调决策 | 让歌落在世界的调上 |
| 入景 | 腾讯混元多模态模型（看图 + 时段 + 地点）→ 能量 / 效价 / 情绪 | 让音色、空间、编配贴合眼前的画面 |
| 推荐与内容（原有能力） | 读懂此刻选歌、有依据的推荐理由、冷启动、声音画像、内容审核 | 地点层的发现与社区 |

大模型默认接腾讯混元（OpenAI 兼容接口，可替换）。不配置时自动降级为本地规则引擎，界面会如实标注。对拍和定调不依赖大模型，完全在本机实时运行。

## 七、部署上线（Demo 链接）

在你自己的电脑上执行（需要先配置 SSH 密钥）：

```bash
./deploy/deploy.sh root@<服务器IP>
```

部署完成后访问 `http://<服务器IP>/`。注意：

- **麦克风和定位在浏览器里都要求 HTTPS**（localhost 除外）。纯 `http://IP` 访问时，共鸣模式拿不到麦克风，歌会照常播放，但不会对拍和定调。所以 Demo 一定要配 HTTPS：准备一个域名，解析到服务器后加一层 Caddy（`caddy reverse-proxy --from 你的域名 --to :80`），会自动申请证书。
- 没有定位时，页面会提供"使用示例位置体验"按钮。
- 接入大模型：在服务器的 `/etc/musichere.env` 里填 `AI_API_KEY`，然后执行 `systemctl restart musichere`。
