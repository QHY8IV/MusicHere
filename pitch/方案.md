### 作品简介（一句话）

走到一个地方，就能听到这里的人留下的歌：AI 读懂此刻为你挑歌，用这里真实的故事出题考你"有多懂这里"，再把一首歌装进漂流瓶，留给下一个路过的陌生人。

### 创作思路

音乐推荐几乎都在回答"你是谁"，很少回答"你在哪、此刻是什么样"。江边的晚霞、深夜的书店、天台 livehouse 的一场即兴，都有一首最合适的歌。但这种"应景"只在当时那个人心里，人走了也就没了。

我们想把歌钉在地点上，让城市里的每个角落都有自己的背景音乐，并且让人**玩**起来：

- **听**：路过的人留下应景的歌，记下这里常听的歌和现场听到的歌。后来的人拍一张照片或说一句心情，AI 读懂此刻，再从这里的人群记忆里挑歌，每首都附上一句有数据依据的理由。
- **玩**：「此地知音」用这个地点真实沉淀的数据出 5 道题，其中一道由 AI 用 emoji 出谜。在现场答题分数 ×1.2，每个地点都有一张知音榜。
- **遇见**：「声音漂流瓶」只能在现场投放、打卡时才能捡到；去过的地方会变成唱片架上的一张唱片。

## 二、产品方案简介

### 问题洞察

1. **场景化听歌的需求真实存在，但没有被满足。** 散步、通勤、等人的时候，人们会去搜"适合傍晚江边听的歌"。可歌单是给所有人的，它不知道这条江、这个傍晚是什么样。
2. **地点的声音记忆在流失。** 街头艺人的一次即兴、小 livehouse 的一场演出、咖啡馆一直循环的那首歌，没有任何平台记录。
3. **音乐互动停留在屏幕里。** 听歌、评论、打榜都在线上完成，和真实世界没有关系。两个人在同一个地方被同一首歌打动，彼此永远不会知道。

### 解决方案

| 模块 | 用户怎么玩 | AI 做什么 |
| --- | --- | --- |
| **此刻**（首页） | 打开就知道自己在哪个"有歌的地方"，像电台一样一首首往下听，点赞会改变推荐权重 | 每首推荐附一句有依据的理由（"近 30 天 7 人在这里听过，傍晚最常被点播"） |
| **听这里** | 拍一张照片 / 说一句心情 | 多模态模型把画面和心情解析成情绪坐标，再从附近的人群记忆里挑 6 首；数据不够时补充"AI 新发现"，一键留在这里 |
| **此地知音** 🎮 | 5 道题：这里最受欢迎的歌、哪首歌在这里有过现场、什么时候最热闹、这里听起来像什么情绪、留言的人在听哪首……逐题揭晓冷知识；速度和连对有奖励，在现场 ×1.2，冲知音榜 | 用 emoji 给这里的一首歌出谜（谜面不能泄露歌名和歌手，否则自动换成规则谜面） |
| **地点** | 三类歌单：应景 / 常听 / 现场；打卡、留言 | AI 声音画像：情绪构成、24 小时热度、常听歌手，再加一句"这里听起来像……" |
| **声音漂流瓶** | 在现场投下一首歌和一句话，下一个来打卡的陌生人会捡到 | "帮我写"起个头 |
| **唱片架 / 明信片** | 去过的地方各收一张唱片，贴纸颜色是那里的情绪；一键导出声音明信片 | 明信片文案 |
| **安全** | — | 规则 + 大模型双重审核留言、漂流瓶和分享语 |

大模型默认接腾讯混元（OpenAI 兼容接口，可替换）。没有配置密钥时，所有 AI 能力自动降级为本地规则引擎，界面会如实标注，Demo 在任何环境下都能完整跑通。

## 三、对照评审标准

### 用户价值：打动人，解决真实的音乐场景需求

- **出门的每一刻都有"对的歌"**：推荐依据的是这个地点、这个时段、这个人群，而不只是你的历史口味。
- **"玩"有内容可玩**：知音挑战的题目全部来自真实数据，所以每个地方的题都不一样，玩完会真的更了解这个地方。
- **陌生人之间的温度**：漂流瓶、留言、知音榜让同一个地点的人隔着时间互相看见。
- **记录被忽视的现场**：街头艺人和小型演出第一次有了"在这里唱过"的记录。

### 可行性：产品逻辑与技术路径清晰，Demo 完成度高

- 一套代码覆盖 **iOS / Android / Web**（Expo / React Native），后端 Node.js + SQLite，**一条命令部署上线**。
- **服务端 95 项自动化测试**（包括用模拟大模型服务验证调用、解析、超时降级、谜面防泄露）。**端到端测试 18 步**覆盖完整用户流程，演示视频就是端到端测试录下来的。
- 猜歌的答案只存在服务端，逐题提交、服务端计时，防止作弊；打卡和投瓶要校验距离，内容真实。
- 落地路径：接入 QQ 音乐曲库与播放 SDK → 听歌识曲自动记录"现场" → 商家 / 景区认领地点。

### 创新性：切入角度新、思路有突破

1. **推荐的主语从"人"换成"地点 + 此刻"**：同一首歌在不同地点有不同的意义。
2. **用地点的人群记忆出题**：音乐游戏不再是听前奏抢答，而是"你有多懂这个地方"。题库随用户的真实行为自动生长，不需要人工出题。
3. **只能在现场完成的玩法**：打卡、漂流瓶、现场加成，把线上的音乐互动拉回真实世界。
4. **可解释的 AI**：每一句推荐理由、每一道题的冷知识，都来自这里真实发生过的数据。

## 六、部署上线（Demo 链接）

在你自己的电脑上执行（需要先配置 SSH 密钥）：

```bash
./deploy/deploy.sh root@<服务器IP>
```

部署完成后访问 `http://<服务器IP>/`。注意：

- 浏览器只在 HTTPS 下允许网页读取定位。用纯 `http://IP` 访问时，页面会提供"使用示例位置体验"按钮，评委不在现场也能体验完整流程。有域名的话，前面加一层 HTTPS（例如 Caddy），真实定位就能用。
- 接入大模型：在服务器的 `/etc/musichere.env` 里填 `AI_API_KEY`，然后执行 `systemctl restart musichere`。
- 云服务器的安全组需要放行 TCP 80。
